# twscrape4j — Java X/Twitter Scraping Library

## Overview

Build `twscrape4j`: a Java 25+ library for scraping X/Twitter's internal GraphQL API. It manages
a pool of authenticated accounts, rotates them on rate limits, and exposes a clean `Stream<T>`
API backed by virtual threads. Modeled after the Python library
[twscrape](https://github.com/vladkens/twscrape) but designed idiomatically for Java.

Key benefits:
- No official API key required — uses browser cookie auth
- Transparent account rotation; consumers just pull from a `Stream`
- Pluggable account storage (SQLite default, any JDBC target possible)
- Browser-realistic TLS fingerprint via Conscrypt

## Context (from brainstorm)

- **Language / runtime**: Java 25+, single Maven module
- **HTTP**: Apache HttpClient 5 per-account client, Conscrypt SSL provider for JA3 fingerprinting
- **JSON**: Jackson; all models expose `.raw()` returning `JsonNode`
- **Storage**: `AccountRepository` interface; `SqliteAccountRepository` via JOOQ (open-source edition, no code-gen — use DSL directly against SQLite)
- **Concurrency**: virtual threads (Project Loom); `Thread.sleep()` on virtual threads for rate-limit backoff (no structured concurrency needed)
- **Lombok**: used in non-record classes (`@Slf4j` for logging, `@Builder` where constructors are complex); not used on records
- **Reference**: [twscrape Python source](https://github.com/vladkens/twscrape) for GraphQL
  operation IDs, required headers, and cursor/pagination shapes

## Solution Overview

A layered design where Twitter GraphQL operations are thin wrappers that know only their
`operationId`, `operationName`, variables, and how to parse the JSON response. The `AccountPool`
handles all concurrency and rotation concerns. `TwScrape` is a facade that wires the two together
and exposes lazy `Stream<T>` via a `PaginatingSpliterator` that fetches the next cursor page on
`tryAdvance`.

## Technical Details

**Pagination**: Twitter's cursor-based pagination returns a `next_cursor` string. A generic
`PaginatingSpliterator<T>` fetches one page at a time, parsing cursor from response and stopping
when cursor is absent or empty.

**Rate limit signals**: `429` HTTP status OR `errors[].code == 88` in the JSON body → mark
account `lockedUntil = Instant.now() + reset window from headers`. `AccountPool.acquire()` parks
the virtual thread until the soonest reset expires.

**Headers required on every call**: `authorization: Bearer <app bearer token>`,
`x-csrf-token: <ct0 cookie>`, `x-twitter-auth-type: OAuth2Session`,
`x-twitter-client-language: en`, `x-twitter-active-user: yes`, `content-type: application/json`.

**TLS fingerprinting**: Conscrypt registered as highest-priority `java.security.Provider` at
`TwScrape` construction time; Apache HC5 `SSLConnectionSocketFactory` built from Conscrypt
`SSLContext`.
